# 좌표 및 시간 기준 v1

상태: 이슈 #9 구현 기준 초안. 팀 리뷰 전이며, 실제 공간 보정과 판정 정확도는 미검증입니다. [분석 계약](analysis-contracts.md)과 함께 사용합니다.

## 기준 영상

디코더에서 회전 메타데이터를 적용해 바로 세운 영상을 `upright_unmirrored_pixels`로 정의합니다. 반전하지 않습니다. 모든 모듈의 반환 좌표는 이 영상 기준입니다. 회전이 이미 적용된 디코더 결과에 다시 회전하지 않도록 입력 단계에서 확인합니다.

- x는 오른쪽, y는 아래, 원점은 왼쪽 위입니다. 단위는 pixel, 좌표는 유한 실수입니다.
- 점의 범위: `0 <= x < width`, `0 <= y < height`.
- 박스는 `[xmin,ymin,xmax,ymax]`, 오른쪽·아래는 제외하는 경계이며 xmax=width, ymax=height를 허용합니다. 빈 박스는 유효하지 않습니다.
- 존의 기하 경계와 박스의 메모리 인덱싱은 다릅니다. 존 경계 접촉 판정은 별도 기하 계산으로 처리합니다.
- cm와 pixel을 같은 필드에 넣지 않습니다. 실제 공간 좌표는 현재 계약에 포함하지 않습니다.

## 전처리와 역변환

표시된 기준 영상에서 crop 원점 `(cx,cy)`를 빼고 x/y 배율 `(sx,sy)`로 resize한 뒤 padding `(px,py)`를 더했다면:

`xm = (x-cx)*sx + px`, `ym = (y-cy)*sy + py`

반환 시 `x = (xm-px)/sx + cx`, `y = (ym-py)/sy + cy`를 적용합니다. 배율은 양수여야 합니다. letterbox는 실제 적용한 배율·패딩을 기록합니다. 정규화된 모델 좌표는 모델 입력 폭·높이를 먼저 곱합니다. 박스와 관절도 동일하게 복원합니다. 패딩에만 있는 검출은 제거하고 원본과 겹치는 박스는 경계로 자릅니다.

예: crop=(100,50), scale=(0.5,0.5), pad=(0,40), 모델 점=(150,140)이면 기준 점=(400,250)입니다.

앱 화면 표시의 회전·반전·fit-center 변환은 표시 단계에만 적용합니다. 서버 기준 좌표를 덮어쓰지 않습니다. 홈플레이트 평면 Homography를 공중의 공이나 관절에 그대로 적용해 3D 좌표로 해석하지 않습니다.

## 식별자와 시간

- `video_id`: 데이터 관리 규칙의 원본 식별자.
- `frame_index`: 원본 디코딩 순서 기준 0부터 시작. 크롭·클립에서도 원본 번호 유지.
- `pitch_id`: 원본 영상과 연결되는 투구 식별자. 투구 미선택 시 null.
- `pts_ms`: 원본 첫 표시 프레임 대비 미디어 시간. 모르면 null. VFR은 실제 PTS를 사용합니다.
- `time_source`: `container_pts`, `estimated_cfr`, `unknown`. CFR 확인 없이 index/FPS를 시간으로 만들지 않습니다.
- 화면 녹화·슬로모션의 pts_ms를 실제 비행 시간으로 해석하지 않습니다. 실제 시간 환산은 촬영 FPS·재생 배속이 검증된 경우에만 별도 처리합니다.
- 서버 수신 시각은 촬영 시각이 아니며 지연 측정용 별도 값입니다.
- 누락 프레임을 새 연속 번호로 재번호화하지 않습니다. 같은 frame_index 결과는 중복 소비하지 않으며 시간 역전은 오류 처리합니다.

## 저장 라벨과의 관계

labels-v1의 video_id, pitch_id, frame_index, pts_ms, image_width, image_height와 좌표 공간을 그대로 사용합니다. 검출 결과는 정답 라벨을 덮어쓰지 않습니다. 라벨의 `unknown`은 미주석/근거 부족이고 런타임의 `unjudgeable`은 분석 후 판정 불가입니다. 자동 결과를 라벨로 옮길 때 draft로 만들고 사람이 검토합니다.
