# 타자 자동 선택·수동 홈플레이트 고정 (#19)

폰 1대의 투수 뒤쪽 영상용 초기 인식 파이프라인입니다. 학습된 역할 분류기나 검증된 ABS가 아닙니다. #11의 Pose 추출과 높이 계산을 재사용하며, #12는 현재 main에 안내 문서만 있어 홈플레이트 후보 모듈을 새로 작성했습니다.

## 입력과 좌표

#10의 testset-v003 manifest가 지정한 analysis 이미지와 ignore-mask를 사용합니다. 원본 영상·라벨은 수정하지 않습니다. 영상 ID와 원본 프레임 번호를 유지하고, 기준 좌표는 upright_unmirrored_pixels입니다. 화면 녹화 PTS는 미디어 시간일 뿐 실제 투구 비행 시간이 아닙니다.

보정/UI 영역은 모델 입력에서 제거하고, 해당 마스크와 박스가 겹치는 인물 검출은 선택 근거에서 제외합니다. 홈플레이트 후보와 수동 앞변도 마스크와 겹치면 거부합니다. 부분 가림에서도 인물 박스 전체를 제외하는 보수적인 정책이므로 사용 가능한 관절이 남아 있어도 검출률이 낮아질 수 있습니다.

## 타자 선택

- 전체 화면의 Pose 사람 검출에서 양손 거리, 어깨·골반 대비 손 높이, 주변 작은 사람과의 배치를 점수화합니다.
- 양손이 가까운 준비 자세를 우선하며 좌타·우타의 화면 좌우를 고정하지 않습니다.
- 역할 점수 0.75 이상, 차순위와 차이 0.12 이상일 때 자동 선택합니다. 이 점수는 확률이 아니므로 confidence는 null로 둡니다.
- 이전 박스와 IoU 0.4 이상인 후보는 유지 점수를 받습니다. 비슷한 후보가 있으면 선택하지 않습니다.
- 누락 시 이전 박스를 현재 검출로 출력하지 않습니다. 3회 누락 또는 15프레임 초과 간격이면 이전 박스 연결을 해제합니다.
- 영상이 바뀌면 초기화하고, 시간 역전·중복 프레임은 거부합니다. ROI 수동 보정과 reset을 지원합니다.

고정 카메라에서의 기초 박스 연결입니다. 스윙 중 처음 시작하는 영상, 번트, 투수와 타자의 유사 자세, 큰 이동·교차·화면 전환에서는 실패할 수 있습니다. 사람 재식별·카메라 이동 감지 모델은 없습니다. 실험 결과를 일반적인 역할 인식 정확도로 해석하지 않습니다.

## 홈플레이트와 존 연결

타자의 발 주변에서 HSV 밝은 저채도 영역을 찾고 형태학 연산·윤곽선·볼록 다각형 조건으로 후보를 만듭니다. 후보 polygon/bbox는 주황색으로 표시합니다. 신발·라인·가려진 흰 조각도 후보가 될 수 있어 이 단계만으로 홈플레이트 앞변을 확정하지 않습니다.

자동 앞변이 검증되지 않은 결과는 status=missing, reason=manual_confirmation_required, front_edge_xy=null로 반환합니다. 후보가 없으면 no_detection입니다. 자동으로 그럴듯한 존 폭을 만들어내지 않습니다. 실제 보이는 앞변 두 점을 사용자가 지정하면 source=manual, confidence=null로 기록합니다. 현재 기본 경로는 수동 앞변을 영상별로 한 번 지정해 유지하는 방식입니다. 아래 고정 카메라 동작을 참고하세요.

pose의 상·하단이 유효하고 plate 앞변이 유효할 때 `zone_candidate()`가 기준 프레임의 image_rect_approx_v1 사각형을 반환합니다. 이것이 #18에서 선택·고정할 입력입니다. locked=false이며 자동 투구 감지·고정이나 실제 공간 판정은 하지 않습니다. 홈플레이트 확인이 안 된 프레임은 수동으로도 추측해서 지정하지 않습니다.

## 실행

저장소 루트에서 실행합니다. data-root는 실제 자료가 저장된 저장소 루트입니다. 다른 worktree에서 자료를 읽기만 할 수 있습니다. 출력 경로는 새 폴더여야 합니다.

```powershell
.venv/Scripts/python.exe server/scripts/recognize_scene.py --data-root C:/path/to/data-repo --model C:/path/to/yolo11s-pose.pt --output outputs/recognition-01 --device 0
```

CPU는 --device cpu를 사용합니다. 기본 imgsz는 960이며 변경하면 결과가 달라집니다. 결과는 results.jsonl, report.json, 프레임별 JPG, review.html입니다. review.html을 브라우저에서 열면 모든 선택·후보·실패를 볼 수 있습니다. 수동 박스 라벨은 선택에 사용하지 않고 추론 후에만 초안 비교에 사용합니다.

## 수동 선택·수정

```powershell
.venv/Scripts/python.exe server/scripts/edit_scene.py --data-root C:/path/to/data-repo --frame import20261029_c01_v002:24 --output outputs/corrections.json
```

창에서 첫 두 번 클릭으로 타자 박스를 지정합니다. 실제 앞변이 보일 때만 세 번째·네 번째 클릭으로 양 끝점을 지정합니다. S 저장, R 다시 선택, Esc 취소입니다. 타자 박스만 저장할 수도 있습니다. 기존 JSON의 다른 프레임은 보존하며 같은 프레임은 새 선택으로 대체합니다. 기존 앞변을 지우려면 R 후 타자 박스만 선택해 저장합니다. 화면 표시 배율은 저장할 때 원본 좌표로 환산합니다.

```powershell
.venv/Scripts/python.exe server/scripts/recognize_scene.py --data-root C:/path/to/data-repo --model C:/path/to/yolo11s-pose.pt --output outputs/recognition-corrected --device 0 --overrides outputs/corrections.json
```

ROI는 인물 검출 선택을 보정하며 검출되지 않은 관절을 생성하지 않습니다. 모델이 타자를 검출하지 못한 작은 타자 영상은 ROI만으로 해결되지 않을 수 있습니다. 입력 예:

```json
{"video_id:frame_index": {"roi": [100,100,300,500], "reset": true}}
```

앞변을 명확히 확인한 경우에만 `front_edge_xy: [[x1,y1],[x2,y2]]`를 추가합니다. 예제 숫자는 실제 자료의 정답이 아닙니다.

6개 영상의 보정본 38개 프레임에 YOLO11s Pose, imgsz=960, GPU device=0을 적용했습니다. 입력 manifest SHA-256: `3a2b77781231f1edc63774418a83d689222d748ea9bb227484cde65a55593e58`. 모델 해시는 report.json에 기록합니다.

선택된 21프레임 모두 높이 계산 조건을 만족했습니다. 초안 라벨은 독립 검토 전이며 동일 개발 자료에서 관찰한 결과이므로 100% 정확도라고 주장하지 않습니다. 샘플은 듬성듬성한 선택 프레임이므로 전체 영상의 연속 추적 안정성·FPS 평가도 아닙니다.

홈플레이트 자동 확정 및 자동 존 배치 성공은 0프레임입니다. 15프레임의 흰 윤곽 후보는 신발·라인과 혼동될 수 있으며, 실제 앞변 정답이 없어 자동 승격하지 않았습니다. 실영상에 임의 수동 앞변을 지정하지 않았습니다. 수동 앞변→존 배치 연결은 합성 좌표로 단위 테스트했습니다.

기존 6개 + 신규 6개 테스트 통과: 자동 선택·유지·누락 해제, 모호함·수동 선택, 시간 역전·초기화, 마스크 배제, 합성 plate 후보의 미확정 상태, 수동 앞변·존 연결·잘못된 입력 거부. compileall, git diff --check 통과. 대표 6장 시각 검토 및 38개 결과 저장 확인. 클릭 편집기 문법 검사는 통과했으나 실제 사용자 클릭 동작은 미검증입니다.

위 표는 기존 자동 후보 실험 결과입니다. 이후 사용자 결정에 따라 자동 홈플레이트 식별은 19번 완료 범위에서 제외하고 수동 지정 유지로 대체했습니다.


## 현재 기본 동작: 한 번 지정하고 유지

자동 타자 선택은 유지하고 홈플레이트는 아래 명령으로 두 점만 지정합니다. 기존 자동 윤곽 모듈은 실험용으로 보존하되 기본 실행기에서는 사용하지 않습니다.

```powershell
.venv/Scripts/python.exe server/scripts/edit_scene.py --data-root C:/path/to/data-repo --frame import20261029_c01_v002:24 --output outputs/plate.json --plate-only
.venv/Scripts/python.exe server/scripts/recognize_scene.py --data-root C:/path/to/data-repo --model C:/path/to/yolo11s-pose.pt --output outputs/recognition-fixed --device 0 --overrides outputs/plate.json
```

두 번 클릭 → S 저장. R은 저장 전 다시 그리기, D는 해당 프레임부터 기존 홈플레이트 고정을 해제하는 이벤트 저장, Esc는 취소입니다. 같은 영상의 나중 프레임에서 새 앞변을 저장하면 그 시점 이후 새 좌표로 교체됩니다. 수정 파일은 다시 실행할 때도 재사용됩니다.

- 같은 video_id·해상도에서 지정 프레임 이후 유지합니다. 이전 프레임에 역적용하지 않습니다.
- 영상 ID·해상도가 바뀌면 해제합니다. 카메라 이동·줌 변경은 자동 감지하지 않으므로 사용자가 D로 초기화하거나 새 두 점을 지정해야 합니다.
- 타자 선택 실패 시에도 홈플레이트 좌표는 유지하지만 존은 만들지 않습니다.
- 마스크가 앞변과 겹치는 프레임은 무효로 표시하고 존 생성을 보류합니다.
- 재지정 값이 잘못되면 오래된 좌표로 되돌아가지 않습니다.
- 홈플레이트만 고정합니다. 투구 기준 자세에 따른 존 높이 고정은 #18 범위입니다.
- sparse manifest에 없는 프레임 번호의 보정 이벤트도 다음 분석 프레임부터 적용합니다. 보정 좌표는 같은 해상도·고정 구도에서 작성해야 합니다.

### 실제 동작 확인

Windows OpenCV 편집 창을 띄워 두 점이 표시된 상태에서 S 저장을 수행했습니다. 저장된 JSON에는 타자 ROI 없이 v002:24의 front_edge_xy만 들어갔습니다. WIN32에서 WND_PROP_VISIBLE 검사로 창이 바로 종료되던 문제를 재현해 WND_PROP_AUTOSIZE 검사로 수정했습니다.

저장 파일을 실제 YOLO 분석에 전달해 총 38프레임을 다시 실행했습니다. v002의 24~38번 선택 프레임 8개 모두 동일한 앞변과 reference_frame_index=24를 유지했고, 타자 선택 성공 6개에서 존이 생성됐습니다. 모호한 2개는 존을 만들지 않았습니다. 나머지 5개 영상에는 이 좌표가 적용되지 않았습니다. 이 클릭 좌표는 동작 검증용 수동 입력이며 홈플레이트 정답·공간 정확도 검증은 아닙니다.

단위 테스트 총 14개 통과. 새 테스트는 좌표 유지·재지정·초기화, 영상·해상도 변경 해제, 마스크 겹침, 잘못된 재지정 후 이전 값 미복원을 검증합니다. 실제 분석 JSONL에서도 8프레임 유지·6개 존·다른 영상으로 전파 없음의 조건을 확인했습니다. 결과는 outputs/issue19/persistent-final/review.html에서 확인합니다.
