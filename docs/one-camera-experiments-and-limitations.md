# 폰 한 대 야구 판정: 실패한 시도와 현재 한계

작성일: 2026-10-31 (KST)

## 문서 범위와 증거 수준

이 문서는 구현 과정에서 결과가 기대에 못 미쳤던 접근을 보존한다. 수치가 산출되거나 영상에 점이 찍힌 것과 실제 공 추적·포구·플레이트 통과가 맞았다는 것은 다르다.

- **재현 확인:** 현재 로컬 산출물과 이번 비교 실행에서 확인한 내용.
- **대화에서 보고됨:** 이전 개발 중 사용자 피드백으로 확인한 현상. 이번에 과거 버전을 다시 실행한 것은 아니다.
- 실패 기록을 남기기 위해 기존 결과 파일이나 사용자 지정 존을 덮어쓰지 않는다.
- 경기 #46의 P34는 사용자가 이후 실험에서 제외하도록 요청했다. 과거 실패 사례로는 기록하되 최신 재분석에서 제외했다.

## 1. 초기 검출·추적·종료 접근

아래 항목은 대화에서 보고된 문제를 요약한 것이다. 각 버전의 정확한 성공률이나 원인을 소급해서 단정하지 않는다.

| 접근 | 보고된 실패 | 변경한 방향 / 남은 문제 |

| 홈플레이트 자동 검출 | 홈플레이트를 안정적으로 찾지 못함 | 사용자가 존·플레이트 기준을 직접 지정하고 고정 카메라에서 재사용 |
| 투구 시작 자동 검출 | 실제 투구가 많이 누락됨 | 다리 키킹·포즈·손목 기반 트리거를 시험했으나 최종적으로 수동 시작 구간 사용 |

| 공 궤적 후보 연결 | 신발·배트·고정 배경 등이 공 후보로 이어짐 | 공개 공 검출 모델로 개선을 시도했지만 후보 정체성 오류는 남음 |
| 자동 가상 존 | 위치·크기가 부자연스러운 사례가 많음 | 사용자가 직접 지정한 존을 기준으로 변경 |
| HTML 결과 제공 | 사용자가 페이지를 열지 못하는 일이 반복됨 | 로컬 HTTP 서버와 직접 재생 가능한 MP4·이미지를 함께 제공 |

관련 기존 코드·문서: `server/src/strikezone/ball/arrival.py`, `role_glove.py`, `wrist_corridor.py`, `docs/manual-start-fixed-plate-issue23.md`, `docs/role-glove-issue23.md`, `docs/wrist-corridor-issue23.md`. 이 목록은 과거 접근을 찾기 위한 포인터이며 각각의 성공률 증명은 아니다.

## 2. 크기 기반 플레이트 통과 시점 추정

### 2.1 밝기 마스크와 최소 포함 원

기존 방식은 공 후보 주변 48×48 패치에서 밝은 연결 영역을 고르고, 모든 마스크 픽셀 모서리를 감싸는 **최소 포함 원**을 만들었다. '가장 큰 원'이 아니다.

실패:

- 중심 주변 고정 반경에 공·번짐이 닿으면 마스크가 거부됨.
- 어두운 공 외곽은 잘리고, 밝은 고정 배경이 공 크기로 측정되는 경우가 있었음.
- 검출점은 있어도 크기는 없는 상태가 생김. 위치 검출과 지름 측정은 서로 다른 단계다.

수정: 앞뒤 프레임의 중앙값 배경과 색상 차이를 사용하는 마스크로 변경. 경기 #46의 547개 추적 후보에서 크기 산출 개수가 359→411로 증가했다. 이는 측정 개수 증가이며 정확도 향상률은 아니다.

증거: `<LOCAL_VIDEO_ROOT>/GAME_VID_000046/마스크개선/summary.json`, `measurements.json`, `index.html`.

### 2.2 번짐 전체를 실제 공 지름으로 사용

최소 포함 원은 번짐까지 포함한다. P07 f4345에서 포함 원 지름은 약 30.81px, 가로 폭은 27px였다. 이 값을 실제 구형 공 지름으로 그대로 쓰면 거리를 잘못 해석할 수 있다.

기존 수식:

- `q(t)=1/d(t)`를 시간의 1차식으로 맞춤.
- `x(t)q(t)`, `y(t)q(t)`를 2차식으로 맞춤.
- 목표 크기 = 지정한 플레이트 폭 × `(9.125 / π) / 17`.
- 목표 크기에 도달하는 시간을 구한 뒤 그 시간의 화면 위치를 계산.

독립적인 이상적 핀홀 투영 데이터에서는 알려진 시각·좌표를 복원했다. 단순 연산 오류가 확인된 것은 아니지만, 관측 크기와 모델 가정이 실제 영상에 맞는다는 뜻은 아니다. 중력 상수를 사용한 보정된 3D 탄도 모델도 아니다.

### 2.3 짧은 관측으로 긴 시간 외삽

P07은 f4337~4346, 약 0.30초 관측으로 포함 원 기준 f4394.86을 예측했다. 마지막 관측에서 약 1.63초 뒤이고, 좌표는 약 (1920, 2047)로 화면 밖이었다.

수정: 마스크 가로 폭 사용, 미래 예측 범위를 `min(관측 시간 길이, 0.25초)`로 제한. 불안정·범위 밖 결과는 `rejected_candidate`에 진단값으로 보존하고 `candidate`에서는 제외.

실패가 남는 이유: 이 제한은 무리한 결과를 내보내지 않는 장치이지, 실제 도착점을 알아내는 해결책이 아니다. 사용자가 대략적인 판정을 원했는데 보류만 늘어나는 문제로 이어졌다.

증거: `server/src/strikezone/ball/size_forecast.py`, `outputs/issue26/render_width_comparison46.py`, `GAME_VID_000046/가로폭예측영상/results.json`.

### 2.5 DeFMO 복원

저자 공개 DeFMO 코드와 사전학습 가중치를 사용했다. 입력은 128×96 원본 영역을 320×240으로 확대했고, 출력 폭은 원본 픽셀로 환산했다. 9개 노출 내 시점을 복원했다. 추가 학습은 하지 않았다.

실패:

- P07 f4345: 가로 폭 27px, 수직 두께 20.48px, DeFMO 중간 시점 폭 36px(9시점 중앙값 40.4px).
- P34처럼 공 대신 사람을 추적한 후보에서는 사람 영역까지 복원했다.
- 지름을 아는 합성 영상의 원래 래스터 공 폭 21px에 대해 수직 두께 19px, DeFMO 28~31.6px였다.
- 선명하게 복원된 것처럼 보이는 결과를 실제 지름 정답으로 간주할 수 없었다.

판단: 이 데이터에서는 수직 두께가 더 안정적인 경향을 보였지만 실제 크기 정확도는 미검증. DeFMO 복원을 운영 판정으로 채택하지 않았다.

증거: `GAME_VID_000046/번짐방법비교/measurements.json`, `synthetic-test.json`, `model-provenance.json`, `outputs/issue26/test_deblur_methods46.py`.

### 목표 크기 검증 실패

P26에서는 약 f17787에 공이 글러브와 겹치기 시작하는 모습을 확인했다. f17785·17786의 수직 두께는 19.49·19.77px였다. 목표 14.37px와 큰 차이가 있다.

그러나 포구와 플레이트 통과는 다른 시점이며, 지정한 존 폭이 실제 플레이트의 투영 폭과 같은지 검증하지 않았다. 따라서 목표를 19.77px로 바꾸거나, 카메라 각도만을 원인으로 단정할 근거는 없다.

마스크 경계도 민감했다. 밝기차 임계값 22%→50%에서:

- P26 f17786: 19.77→16.90px
- V06 f1355: 7.39→5.40px
- V07 f2723: 7.98→5.09px

목표에 맞추려고 임계값을 조절하면 검증이 아니라 결과 맞추기가 된다. 이 비교에서는 실제 분석 파라미터를 변경하지 않았다.

## 4. 현재 선택: 도달 위치 기반 참고 판정

사용자가 정확한 3D ABS보다 폰 한 대로 대략적인 결과를 내는 것을 우선하도록 요청했다.

구현: `server/src/strikezone/judgment/receiver_reference.py`

- 저장된 존으로부터 초기 포수 영역을 넓혀 만든다. API는 직접 지정한 `receiver`도 받을 수 있다.
- 기존 공 추적 후보에서 포수 영역 근처 방향 변화·감속·검출 소실을 찾는다.
- 소실은 추적이 끝난 것만으로 확정하지 않고 뒤 3프레임의 검출 후보를 확인한다. 그래도 실제 포구와 동일하지 않다.
- 도달 후보 1프레임 전 관측을 우선 사용한다. 짧은 가림은 제한된 보간 또는 최대 2프레임 외삽으로 처리한다.
- 도달 후보가 없으면 포수 영역에 가장 가까운 실제 관측으로 대체한다.
- 위치가 존 안/밖인지에 따라 스트라이크 추정/볼 추정을 내고, 경계 허용 폭 안이면 경계로 표시한다. 허용 폭은 `max(3px, 존 폭의 8%)`인 경험적 값이다.
- 관측이 없을 때는 판단 불가다. 신뢰도 low/medium은 확률이 아니다.
- `confirmed_catch=False`, `confirmed_plate_crossing=False`, `validated=False`를 유지한다.

검증 범위:

- 경기 #46의 P34 제외 44개 + 폰 2개 = 46개.
- 스트라이크 추정 9, 볼 추정 30, 경계 4, 공 관측 없음 3.
- 소실 근거 27, 최근접 관측 대체 11, 감속 2, 방향 변화 3, 관측 없음 3.
- 이 숫자는 정확도나 정상 포구 성공률이 아닌 출력 분포다.
- P01/P07/P26/V06-R03/V07-R04 표시 영상 5개, 총 858프레임 디코딩 검증.
- 기능 단위 테스트 6개: 소실, 최근접 대체, 경계, 관측 없음, 짧은 보간, 예측점을 관측으로 사용하지 않음.

남은 한계:

1. 포수 도달 직전 위치와 실제 플레이트 통과 위치는 다르다.
2. 바운드·배트 접촉·글러브 이동을 정상 포구와 구분하지 못할 수 있다.
3. 오검출된 공 후보가 있으면 잘못된 참고 판정을 낼 수 있다.
4. 포수 영역은 현재 사용자 직접 지정값이 아니라 존에서 유도한 초기 영역이다.
5. 카메라 이동 시 기존 존·영역이 틀릴 수 있다.
6. 영상에 표시한 최종 결과는 전체 구간을 분석한 오프라인 결과이며 실시간 판정 검증은 아니다.
7. 공 반지름과 3D 존 교차를 판정하는 정식 규칙 구현이 아니라, 중심점과 경험적 경계 여유로 만드는 화면상 참고 결과다.
