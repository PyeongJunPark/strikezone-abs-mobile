# 데이터·모델 관리 규칙

## 상태와 저장 위치

기본 구성은 폰 1대 + 노트북이며 모델은 로컬 GPU에서 학습합니다. **팀 외부 공유 위치와 접근 방식은 미정**입니다. 이 문서는 공유 폴더나 사용 권한이 확보되었다는 의미가 아닙니다.

| 위치 | 용도 | Git 관리 |
| --- | --- | --- |
| `data/raw/` | 촬영 원본, 원본별 메타데이터 | 제외 |
| `data/derived/` | 투구 클립, 크롭, 추출 프레임 | 제외 |
| `data/labels/` | 실제 라벨 JSONL | 제외 |
| `data/releases/` | 버전별 파일 목록·분할 목록 | 제외 |
| `models/weights/` | 다운로드·학습 가중치 | 제외 |
| `models/records/` | 실제 학습·모델 기록 | 제외 |
| `outputs/`, `runs/` | 결과 영상·로그·평가 산출물 | 제외 |
| `data/examples/`, `models/examples/` | 합성 예시와 빈 기록 양식 | 포함 |
| `configs/` | 개인 경로 없는 공유 설정 | 포함 |

실제 라벨과 메타데이터도 기본적으로 외부 공유 대상으로 둡니다. 공개 가능한 평가 요약만 검토 후 문서에 옮깁니다. 비공개 폴더 링크·접근 토큰·실명은 공개 저장소에 넣지 않습니다. 공유 위치가 정해지면 저장소 밖의 팀 연락 수단으로 접근을 안내하고 실제 다운로드·권한을 확인합니다.

## 식별자와 파일명

- 촬영 세션: `YYYYMMDD_sNN` (예: `20261029_s01`). 촬영 시작 전에 번호 중복을 확인합니다.
- 원본 영상: `<session_id>_c01_vNNN.mp4`. 한 대이므로 카메라 ID는 `c01`입니다.
- 투구: `<session_id>_pNNN`. 여러 투구가 들어 있는 원본은 하나로 보존하고 파생 클립에 투구 ID를 붙입니다.
- 프레임: `<video_id>_f000123.png`. 프레임 번호는 원본 디코딩 순서 기준 0부터 시작합니다.
- 라벨: `data/labels/<dataset_version>/<video_id>.jsonl`.
- 원본은 편집·덮어쓰기하지 않습니다. 원래 파일명은 메타데이터에 보존하고 복사본으로 식별자를 부여합니다.
- 모든 클립·크롭·프레임은 부모 `video_id`, 원본 프레임 범위와 같은 `split_group_id`를 유지합니다.

## 영상 메타데이터

[data 예시](../data/examples/video.example.json)를 복사해 실제 값을 기록합니다. 예시는 합성 값이며 실제 촬영 기록이 아닙니다.

필수 항목은 식별자, 저장 경로, SHA-256, 출처 유형, 영상 크기·회전, 파일 FPS, 촬영 FPS, 재생 배속, 카메라 배치, 원본 연결, 공유·사용 허용 범위입니다. 모르는 값은 `null`로 두며 파일 FPS를 촬영 FPS로 복사하지 않습니다.

- `source_type`: `camera_original`, `screen_recording`, `external_video`.
- `playback_speed`: 실제 시간 대비 재생 속도. 0.25는 1/4배속, 모르면 null.
- `capture_fps`: 촬영 장치·원본 정보로 확인한 값만 기록합니다.
- `sha256`: 실제 파일의 해시. 빈 예시 값을 실제 배포에 사용하지 않습니다.
- 출처 URL·권한 증빙은 실제 메타데이터 또는 팀 내부 기록에 보관합니다.

## 라벨 저장 규칙 v1

[data 라벨 예시](../data/examples/labels.example.jsonl)는 프레임당 JSON 한 줄입니다. 이 규칙은 **저장용 라벨 형식**이며 앱–서버 통신이나 3차원 판정 규격을 확정하지 않습니다.

- 기준 영상은 회전 메타데이터를 적용해 바로 세운 영상입니다. 좌우 반전은 하지 않습니다. `image_width`, `image_height`는 이 기준 영상의 크기입니다.
- 원점은 왼쪽 위, x는 오른쪽, y는 아래, 단위는 픽셀입니다. 중심점은 실수로 기록할 수 있습니다.
- 박스는 `[xmin, ymin, xmax, ymax]`이며 오른쪽·아래 경계는 제외합니다. YOLO 학습용 정규화 좌표는 변환본으로 별도 생성합니다.
- `frame_index`는 원본 디코딩 순서 0 기반입니다. `pts_ms`는 해당 원본의 첫 표시 프레임 대비 미디어 시간입니다. 실제 촬영 시각과 다르며 모르면 null입니다.
- 공은 `visible`, `occluded`, `out_of_frame`, `uncertain` 중 하나로 기록합니다. 중심·박스를 확인할 수 없으면 null이며 가린 위치를 추측해서 정답으로 만들지 않습니다.
- 존은 영상 평면의 `[xmin, ymin, xmax, ymax]`와 근거·고정 기준 프레임을 기록합니다. 이 사각형이 실제 공간의 정확한 존이라는 뜻은 아닙니다.
- `swing`: `swing`, `no_swing`, `unknown`. 판정은 `strike`, `ball`, `unjudgeable`, `unknown`, `excluded_swing`.
- 판정 근거가 없으면 `unknown`입니다. 포수의 포구 위치나 중계 화면의 겹침만으로 실제 통과 정답을 만들지 않습니다.
- 수동 정답과 모델 예측은 다른 파일에 저장합니다. 검토자 확인 전 라벨은 `draft`입니다.

## 데이터 분할과 버전

촬영 세션 전체를 동일한 `split_group_id`로 묶어 train/val/test 중 하나에만 배정합니다. 외부 영상은 같은 원본과 재편집본을 한 그룹으로 묶고, 같은 장면임을 확인할 수 없으면 평가용에서 보류합니다. 원본 해시 중복도 확인합니다. 같은 투구의 인접 프레임·증강본·크롭본은 서로 다른 분할에 넣지 않습니다.

분할 비율은 데이터 수집 후 정합니다. `dataset-v001`처럼 버전을 붙이고 출시 후 원본·라벨·분할이 바뀌면 새 버전을 만듭니다. manifest에는 모든 파일의 상대 경로·해시, 원본 연결, split_group_id와 분할을 기록합니다. test는 최종 평가용으로 고정하고 모델 선택은 val에서 수행합니다. test 결과를 보고 반복 수정했다면 이를 기록하고 새 평가 세트를 확보합니다.

## 학습·모델·결과 기록

[모델 기록 양식](../models/examples/model-record.example.json)에 모델 ID, 기반 가중치와 해시·출처, 데이터 버전, 코드 커밋과 미커밋 변경 여부, seed, 실행 명령, 설정 파일·해시, Python·패키지·GPU, 평가 분할·수치를 기록합니다.

실행 ID는 `<날짜>_<실험명>_rNN`, 가중치는 `models/weights/<model_id>/`에 둡니다. 같은 이름의 결과를 덮어쓰지 않습니다. 실험 당시 설정과 명령을 `outputs/<run_id>/`에 함께 보존합니다. 미확인 지표는 null로 남깁니다.

## 받기와 검증

공유 위치 확정 전에는 실제 공통 데이터 배포가 완료되지 않은 상태입니다. 확정 후:

1. 사용할 데이터·모델 버전을 선택하고 manifest 및 사용 조건을 확인합니다.
2. 원본·라벨·가중치를 위의 로컬 경로에 배치합니다. ZIP을 쓰는 경우 manifest 경로와 압축 해제 위치를 일치시킵니다.
3. PowerShell `Get-FileHash -Algorithm SHA256 파일경로`로 제공된 해시와 비교합니다.
4. `configs/environment.local.json`에 영상·가중치 경로를 지정하고 [환경 검사](development.md)를 실행합니다.
5. 팀원별 다운로드·접근·해시·실행 확인 결과를 기록합니다. 가중치는 출처와 해시를 확인한 파일만 로드합니다.

## 공유 전 확인

촬영 인물의 촬영·팀 내부 공유·외부 공개 허용 범위와 외부 영상·모델의 사용 조건은 자료별로 확인합니다. 공개 웹에 있다는 사실을 재배포 허가로 간주하지 않습니다. 확인 전에는 실제 영상과 라벨을 업로드하지 않습니다. 현재 제공된 화면 녹화 자료의 이용 조건도 아직 확인되지 않았습니다.
