# 홈플레이트 Homography 보정

상태: 합성(가상 카메라) 데이터로 검증. 2026-11-24 실제 공유 영상으로 동작은 확인했지만, 홈플레이트 꼭짓점이 보이는 영상이 없어 실제 오차는 측정하지 못했습니다.

## 무엇을 하나

홈플레이트 꼭짓점 4~5개를 찍으면 **지면 평면(cm) ↔ 화면(px)** 변환(Homography)을 계산합니다.

- 존 좌우 경계: 홈플레이트 폭 43.18cm에 공 반지름 3.67cm를 더한 위치를 화면 좌표로 반환 (`zone_edges`)
- 앞변 기준 px/cm (`px_per_cm_front`)
- 지면 위 점의 실제 좌표 변환 (`image_to_plate`, 예: 발 위치)
- 자동 검출 후보 검증: 흰색 오각형 윤곽이 홈플레이트 모양인지 확인해 **제안만** 합니다 (`suggested_corners_xy`). 확정은 사람이 합니다.

지면 평면 변환이므로 **공중의 공·관절 좌표를 3D로 해석하는 데 쓰면 안 됩니다** ([좌표 기준](coordinates.md)).

## 좌표와 찍는 순서

홈플레이트 좌표계(cm): 원점은 앞변(투수 쪽) 가운데, +x는 화면 오른쪽 앞 꼭짓점 방향, +y는 포수 방향.

찍는 순서(화면 기준 좌우):

1. 앞변 왼쪽 꼭짓점
2. 앞변 오른쪽 꼭짓점
3. 오른쪽 어깨(옆변과 뒤 대각선이 만나는 점)
4. 뒤 꼭짓점(포수 쪽 뾰족한 점) — 4점만 찍을 때는 생략
5. 왼쪽 어깨

| 점 개수 | 의미 |
| --- | --- |
| 5개 | 점이 하나 남으므로 재투영 오차로 "정말 홈플레이트 모양인지" 확인 가능 |
| 4개 | 항상 정확히 맞아떨어져 검증 불가 → `four_points_exact_fit_unverified` 경고 |

오차 기준: 재투영 오차가 `max(1.5px, 앞변의 3%)`를 넘으면 경고, `max(3px, 앞변의 6%)`를 넘으면 거부(`shape_not_plate_like`).

## 사용

- 판정 웹(`serve_judgment.py`): 2단계 모드에서 **홈플레이트 꼭짓점 5개**를 선택해 찍으면 기존 좌우 두 점 대신 사용합니다. 결과 영상에 주황색 오각형이 그려집니다.
- 파이프라인 설정: `plate_corners`(4~5점)가 있으면 Homography 앞변으로 `plate_points`를 대체합니다. 결과 JSON의 `plate_calibration`에 행렬·오차·px/cm가 기록됩니다.
- 코드: `strikezone.plate.homography.fit_plate(points, (width, height))`

## 한계

- 30fps·원거리 촬영에서는 홈플레이트가 수십 px로 작게 찍혀 클릭 오차의 영향이 큽니다.
- 판정은 여전히 화면상 위치 기반 참고 판정이며, 존 좌우 경계를 실제 플레이트 통과 깊이에 맞춰 옮기지는 않았습니다.
- 자동 검출 후보 제안은 흰색 윤곽이 오각형으로 잡힐 때만 동작합니다. 흙·선·가림이 있으면 수동으로 찍어야 합니다.

## 실제 영상 확인 (2026-11-24)

공유 영상(경기 46·13번, 폰 V06 등)으로 확인한 결과:

- 투수 뒤 먼 거리·낮은 높이에서 찍어 홈플레이트가 **폭 20~90px, 높이 2~3px의 선**으로만 보였습니다. 꼭짓점을 구분할 수 없어 5점 보정의 실제 오차는 측정하지 못했습니다. 폰 영상(V06·V07·V09)에는 홈플레이트가 없습니다.
- G46-P26 프레임에서 자동 검출 후보 2개는 모두 꼭짓점 4개(선·신발)라 제안하지 않았습니다. 잘못된 제안은 없었습니다.
- G46-P26에서 근사 꼭짓점 5개로 웹 업로드 → 분석 → 결과 저장까지 동작했습니다(약 2.08px/cm, 결과 영상 180프레임 디코딩 확인). 잘못된 순서는 한글 오류로 거부됐습니다.

Homography를 실제로 쓰려면 **홈플레이트 기준 프레임을 더 높거나 가까운 위치에서** 찍어야 합니다. 같은 카메라 위치를 유지해야 하므로, 촬영 시작 전에 삼각대를 높게 세우거나 줌을 고정한 채 홈플레이트 흙을 정리해 흰 오각형이 보이게 하는 방법을 권장합니다.
