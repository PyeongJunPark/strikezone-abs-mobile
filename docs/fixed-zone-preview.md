# 기준 프레임 선택과 스트라이크존 고정 (#18)

## 추가: 투구 시작 후보 감지와 존 자동 고정

`--pitcher-roi`를 지정하면 투구 시작 프레임을 직접 입력하지 않고 분석합니다. 지정한 투수 영역에서 3개 연속 프레임이 안정된 뒤, 준비 화면 대비 변화와 직전 화면 대비 움직임이 2개 연속 프레임에서 기준을 넘으면 시작 후보를 확정합니다. 공이 손에서 떨어졌다는 뜻은 아닙니다. 투수 영역·타자 ROI·존 가로 범위는 여전히 수동입니다.

```powershell
.venv/Scripts/python.exe server/scripts/preview_fixed_zone.py --manifest data/derived/issue18-v002-contiguous/manifest.json --video-id import20261029_c01_v002 --model "C:/Users/user/Desktop/스트존/models/yolo11s-pose.pt" --roi 660 240 850 630 --pitcher-roi 40 320 330 680 --zone-x 515 615 --device 0 --output outputs/issue18/new-auto-review
```

자동 모드에서는 **미리보기 재생** 또는 프레임 이동으로 확정 프레임에 도달하면 시작 후보보다 앞선 최근 15프레임 중 마지막 유효 타자 자세로 존을 자동 고정하고 tracking 상태로 전환합니다. 확정 이전 화면에는 미래의 고정 결과를 표시하지 않습니다. 기준 자세가 없거나 시작 후보가 없으면 자동 고정하지 않습니다. 고정 뒤 프레임별 관절 변화는 존에 반영하지 않습니다. 새 투구/설정 변경/수동 고정은 자동 적용을 해제하며, 자동 모드를 다시 켜면 시연을 처음부터 재생합니다.

마스크 영역은 움직임 계산에서 제외합니다. 프레임 누락·크기 변경·분석 영역 부족 또는 큰 배경 변화가 있으면 감지를 중단하고 기존 자동 존도 무효화합니다. 배경 변화 검사는 단순 비율 기준이며 모든 카메라 이동을 감지하는 기능은 아닙니다. 자동 감지는 현재 한 투구 구간에 한 번 적용하며, 여러 투구의 자동 분할·재무장은 후속 범위입니다.

2번 영상의 연속 45장에서는 **시작 후보 11 → 확인 12 → 기준 자세 10**을 얻었습니다. `outputs/issue18/auto-v002-final/`에 결과가 있습니다. 초반 화면이 정지된 녹화 자료이므로 화면 재생 재개와 실제 동작 시작이 혼동될 수 있습니다. 이 결과는 실제 투구 시작 정답·일반화 정확도 검증이 아닙니다. 견제·준비 움직임과 투구 동작을 구분하는 학습 분류기도 아직 없습니다. `validated=false`, `ball_release_confirmed=false`를 유지하며, 공 릴리스 확인은 #20에서 연결합니다.

자동 시작 후보는 `pitch_start.onset_frame_index`, 확정 시점은 `confirmed_frame_index`로 저장합니다. 자동 고정 결과의 `release_frame`은 null이며, 동작 시작을 공 릴리스로 기록하지 않습니다. 임계값은 개발용 고정값(픽셀 차이 20, 준비 대비 변화 비율 0.08, 직전 대비 변화 비율 0.01, 큰 배경 변화 비율 0.15)이며 다양한 촬영 조건에서 검증하지 않았습니다.

추가 후 Python 16개·Node 11개 테스트 통과. 정지 화면, 단발 움직임, 연속 움직임 확인, 마스크, 배경 변화·누락 차단, 과거 유효 자세 선택, 확인 시점 이후 자동 고정과 수동 초기화를 검증했습니다. 아래 수동 사용법과 초기 결과는 수동 모드에 대한 기록입니다.

포인터 보정 이미지에서 타자 관절을 분석하고, 직접 지정한 투구 시작 경계 이전의 기준 프레임을 추천합니다. 선택한 프레임의 높이와 수동 가로 범위로 사각형 존을 고정합니다. 실제 스트라이크/볼 판정이나 홈플레이트 자동 보정은 수행하지 않습니다.

## 실행과 사용

저장소 루트에서 로컬 Pose 모델과 [보정본 manifest](manual-labeling.md)를 지정합니다. `image_path`, `ignore_mask_path`, `frame_index`, `video_id`가 있는 `frames` 목록과 각 파일의 SHA-256을 가진 `files` 목록이 필요합니다. `default_analysis_input`은 `cursor_cleaned_png`여야 합니다. 경로는 저장소 루트 기준입니다.

```powershell
.venv/Scripts/python.exe server/scripts/preview_fixed_zone.py --manifest data/derived/issue18-v002-contiguous/manifest.json --video-id import20261029_c01_v002 --model "C:/Users/user/Desktop/스트존/models/yolo11s-pose.pt" --roi 660 240 850 630 --zone-x 515 615 --release-frame 22 --device 0 --output outputs/issue18/new-review
```

예시는 이 PC의 로컬 모델·실험 자료 경로입니다. 다른 PC는 받은 자료와 모델 경로로 변경합니다. 출력 폴더는 새 경로여야 합니다. CPU는 `--device cpu`를 사용합니다. 실제 데이터·모델·산출물은 Git에 포함하지 않습니다.

출력 `review.html`은 이미지·스크립트를 내장한 오프라인 파일입니다. 브라우저로 직접 열어 사용합니다. `frames.jsonl`에는 관절 결과와 원본 프레임 번호, `report.json`에는 모델·입력 해시, 설정, 후보와 실패 사유가 있습니다.

1. **투구 시작 경계와 종료 프레임**을 지정합니다. 경계는 관찰로 직접 정하는 값입니다. 예시의 22번은 자동 검출이나 검증된 릴리스 정답이 아닙니다.
2. **추천 후보** 또는 프레임 이동으로 기준을 선택합니다. 추천은 경계 이전의 유효 관절 점수와 연속 프레임 간 높이 변화량으로 정합니다. 실제 투구 직전 자세인지 사람이 확인합니다.
3. 존의 **왼쪽·오른쪽 x**를 직접 입력합니다. 타자 선택 ROI와 존 폭은 서로 다릅니다. 홈플레이트 자동 인식은 #19 범위입니다.
4. **현재 프레임으로 존 고정**을 누릅니다. 관절이 유효하지 않으면 거부합니다. 필요하면 **높이 직접 보정**을 켜고 위·아래 y를 입력합니다.
5. **투구 시작 → 프레임 이동/재생 → 투구 종료**로 존 유지 여부를 확인합니다. 고정 뒤 현재 관절이 누락되어도 기준 존은 유지합니다.
6. 다음 투구는 **새 투구 / 다시 설정**으로 초기화합니다. 카메라 이동·화면 전환을 발견하면 해당 버튼으로 현재 존을 무효화하고 다시 고정합니다.
7. **설정·결과 저장**으로 JSON을 다운로드합니다. 같은 입력·모델의 JSON을 불러오면 설정과 기준 프레임을 복원하며, 화면을 확인한 뒤 다시 고정해야 합니다.

## 규칙과 저장 의미

- 기존 `pose-midpoint-v1`: 어깨 평균과 골반 평균의 중간이 상단, 무릎 평균이 하단입니다. 규칙상 실제 경계의 정답이 아닙니다.
- 기준 프레임은 투구 시작 경계보다 앞이어야 합니다. 좌표 순서·유한수·화면 범위를 검증합니다.
- 기준 이전이나 지정한 투구 종료 이후에는 존을 표시하지 않습니다. 화면 크기 변경 시 존을 무효화합니다.
- 투구 중·종료 후에는 기준을 교체할 수 없습니다. 먼저 초기화해야 합니다. 설정 변경은 이전 존을 해제합니다.
- 저장한 `zone`은 `reference_frame_index`, `bbox_xyxy`, `pitch_id`, 계산 방식, 기준 Pose, 설정을 갖습니다. 수동 높이의 confidence는 null, validated는 항상 false입니다. 최종 판정은 unjudgeable입니다.
- 원본 PNG 해시를 검증한 뒤 보정본을 사용합니다. 제외 마스크는 추론 입력에서 검게 가리고, 해당 영역과 4px 주변에 있는 관절은 근거에서 제외합니다. 검게 가린 영상도 모델 오차를 유발할 수 있으므로 검출 성공을 정확도 검증으로 해석하지 않습니다.
- HTML의 JPEG는 표시용입니다. 모델은 PNG 입력을 사용하며 저장 좌표는 원본 크기입니다.
- 정확히 같은 연속 이미지는 추천에서 중복 제외합니다. 압축 때문에 픽셀이 조금 달라진 정지 장면·유사 프레임은 아직 별도 판별하지 않습니다.
- 일부 프레임만 있는 자료도 확인할 수 있지만, 누락 구간을 연속 프레임으로 취급하지 않습니다. UI 재생은 확인용 10장/초이며 실제 비행 시간이 아닙니다.

카메라 이동·화면 전환은 **수동 무효화** 방식입니다. 자동 감지는 구현하지 않았습니다. 투구 시작·종료도 수동 상태 전환이며 공 추적·포구 기반 판정은 #20에서 연결합니다.
