# pose
수동 ROI로 타자를 선택하고 COCO 17관절 Pose 모델에서 어깨·엉덩이·무릎을 추출합니다.

- `detector.py`: Ultralytics 어댑터. 원본 프레임 좌표를 반환합니다.
- `zone.py`: ROI IoU 기반 선택, 모호한 선택 거부, 6개 관절 신뢰도·좌표·기하 검증, 높이 계산, 높이 고정·초기화.
- `server/scripts/preview_pose.py`: 녹화 영상 CLI. JSONL, 미리보기 MP4, 설정·해시·실행 시간 보고서를 새 출력 폴더에 생성합니다.

계산식은 `pose-midpoint-v1`입니다. 어깨 평균과 엉덩이 평균의 중간을 상단, 무릎 평균을 하단으로 사용합니다. 관절 누락·낮은 신뢰도·잘못된 순서에서는 높이를 null로 반환합니다. 수동 ROI는 실제 인물 추적 ID가 아니므로 카메라 이동·타자 교체 시 ROI를 다시 지정하고 초기화해야 합니다.

## 실행

저장소 루트에서 프로젝트 가상환경 Python으로 실행합니다. 영상과 모델은 로컬 파일이어야 하며 출력 폴더는 새 경로를 지정합니다.

```powershell
.venv/Scripts/python.exe server/scripts/preview_pose.py --video "영상경로.mp4" --model "models/yolo11s-pose.pt" --output outputs/pose-run-01 --video-id import20261029_c01_v002 --roi 660 240 850 630 --start 0 --end 44 --lock-frame 0 --device 0
.venv/Scripts/python.exe -m unittest discover -s server/tests -p "test_pose*.py"
```

`--device cpu`로 CPU를 선택할 수 있습니다. ROI는 바로 세운 원본 영상의 x1 y1 x2 y2입니다. GUI 선택은 아직 없으며 숫자로 지정합니다. `--lock-frame`은 원본 0 기반 프레임 번호로 사람이 선택하며 자동 투구 시작 감지가 아닙니다. 해당 프레임이 무효이면 고정을 거부하고 다른 프레임에 자동 재시도하지 않습니다. `--reset-frame 60`으로 수동 초기화 시점을 지정할 수 있습니다. 초기화는 고정을 해제해 LIVE 후보 표시로 돌아갑니다. 다른 프레임에서 다시 고정하려면 새 실행의 lock-frame을 지정합니다.

출력 `pose_height_lock`은 pose 전용 확장 필드이며 완전한 고정 zone 결과가 아닙니다. 기존 pose 필드 이름과 계산식을 유지했습니다. 좌우 홈플레이트 기준은 #12에서 연결하므로 표시 선의 가로 길이는 ROI 폭을 사용하며 스트라이크존 폭으로 해석하지 않습니다. 공통 계약은 변경하지 않았습니다.

영상의 실제 촬영 시간은 불명확하므로 JSONL의 pts_ms는 null, time_source는 unknown입니다. 미리보기는 표시용 고정 30fps이고 속도·실시간 성능 판단용이 아닙니다. 모델 신뢰도는 정확도 확률이 아니며 pose confidence는 사용한 여섯 관절 점수의 최솟값입니다.

높이 고정 이후 관절이 누락되더라도 이전 높이는 유지하고 현재 pose 실패 상태는 별도로 기록합니다. 카메라 이동은 자동 감지하지 않으므로 사용자가 초기화해야 합니다. 본 모듈은 홈플레이트 보정, 자동 투구 상태 전이, 볼·스트라이크 판정을 수행하지 않습니다.

단위 테스트 6개 통과: 공식 계산과 다른 사람 배제, 관절 누락·낮은 점수, 잘못된 기하, NaN/Infinity/범위 밖 좌표, 모호한 후보·검출 없음, 고정·초기화·복사 독립성. 출력 영상 총 115프레임 재디코딩 및 JSONL의 고정 유지·초기화 확인. 대표 프레임을 시각적으로 확인했습니다.

모델 초기화 포함 첫 프레임은 약 1.7초, 이후 모델 실행·선택·계산 평균은 약 7ms였습니다. 소규모 GPU 오프라인 측정이며 영상 읽기·저장·앱 전송을 제외합니다. 수동 관절 정답이 없어 존 정확도·cm 오차는 평가하지 않았습니다. 특히 무릎 관절 중심과 규칙상 경계의 차이는 남아 있습니다.
